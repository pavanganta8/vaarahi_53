# 📸 Snapshots (SCD Type 2) in DBT

Snapshots in dbt are designed to capture the state of raw tables at a specific point in time, building a historical record of changes. This implements **Slowly Changing Dimensions Type 2 (SCD Type 2)**.

---

## 1. What are Snapshots?
Normally, when a database record is updated in place, the old values are lost forever (e.g. if a customer changes their address or a product changes its price).
A dbt snapshot creates a target table that tracks history by adding:
* `dbt_valid_from`: The timestamp when this row version became active.
* `dbt_valid_to`: The timestamp when this row version was superseded (or `NULL` if it is the current active version).
* `dbt_scd_id`: A unique surrogate key generated by hashing the primary key and the record's updated timestamp.
* `dbt_updated_at`: The timestamp when this record was captured.

---

## 2. Snapshot Strategies

dbt supports two strategies to detect when a row has changed:

### ⏱️ Strategy A: Timestamp (Recommended)
* **How it works**: Uses a dedicated timestamp column (e.g. `updated_at`) in the source table. If this timestamp is newer than the snapshot's stored timestamp, dbt knows the row changed.
* **When to use**: Whenever the source system provides a reliable `updated_at` column.
* **Example**: [product_snapshot.sql](product_snapshot.sql)

### 🔍 Strategy B: Check
* **How it works**: Compares a list of columns (or a hashed version of them) to detect changes. If any of the columns' values differ from the active snapshot row, a new snapshot row is written.
* **When to use**: When the source table has no `updated_at` timestamp column, but you still need to track historical changes.
* **Example**: [customer_snapshot.sql](customer_snapshot.sql)

---

## 3. How to Run Snapshots
To compile and execute snapshots, run:
```bash
dbt snapshot
```
* The first execution creates the target snapshot table.
* Subsequent executions compare the source table with the snapshot table, invalidating superseded rows (setting `dbt_valid_to = current_timestamp`) and inserting new active rows (setting `dbt_valid_from = current_timestamp` and `dbt_valid_to = NULL`).
